# Magic History 账号基础：邮箱与 Google 登录

## 状态与已确认决定

用户已选择 Supabase 托管认证，允许在正式域名注册前开发，并回复“确认”通过本规格。不会创建外部账户、开通付费服务、推送 GitHub、迁移正式学生数据或改变当前完整开发者预览的访问范围。

已确认的后续商业规则：APWH U1、U2 免费；一次性购买后账号永久解锁 U3–U9，不自动续费。艺术史不自动包含在这项购买中。服务面向大陆及海外，邮箱是基础入口，Google 是可选入口。价格、支付商户和正式服务器不在本阶段确定。

## 第一阶段范围

1. 主页面右上角增加登录／注册入口，登录后显示邮箱与退出入口。
2. 登录弹窗提供邮箱密码登录、邮箱注册、忘记密码；提供可选 Google 登录按钮。
3. 处理注册确认邮件、登录回调、密码重设页面、会话恢复、退出、网络失败和过期会话。
4. 配置缺失时明确显示“暂未连接账号服务”，禁止发送注册／登录请求，不生成假用户、不模拟成功。可检查界面与表单状态，但不声称真实认证已接通。
5. 交付 Supabase 与 Google 后台配置指南。项目由 Tiffany 持有；需要项目 URL 和 publishable key 配置客户端。Google OAuth 私钥、Supabase service-role／secret key、SMTP 密码不进入前端或 GitHub。

## 架构

保留静态 HTML/CSS/JavaScript，不重写地图或引入 SPA 框架。用独立账号 UI 模块、Supabase 适配器和公开配置文件与主页连接。认证 SDK 使用固定版本的本地打包资源，不把第三方 CDN 当作注册页的必需加载入口。用户密码只提交给认证服务，不写入网站数据库、浏览器自建存储、URL、日志或分析系统。

使用明确的回调页面和 PKCE 流程。回跳仅允许本站预定义页面，不接受任意外部重定向地址。密码重设必须在有效恢复会话中完成。退出后立即清空页面账号状态；无效或过期会话不能继续显示为已认证。不得以浏览器 localStorage 的自定义标志、前端邮箱名单或用户可编辑资料授予管理员／购买权限。

测试环境和将来的正式环境分开配置回调地址。用户后续更换域名而保留同一 Supabase 项目时，账号 ID 保持不变；需要更新允许的回调、邮件链接及 OAuth 配置并重新测试。公开部署前必须实测大陆网络下的认证 API、邮件和登录回调，托管服务的大陆可访问性尚未验证，不作为既定保证。

## UI 与交互

沿用 `assets/map-ui.css` 的字体家族和既有字号变量、首页米色／深色／暖金配色及圆角。仅对账号组件增加局部样式，不修改两个地图的字体、尺寸、配色、知识内容或现有图片。移动端输入框可用16px防止系统自动缩放，其余文本遵守现有层级，不全局放大字体。

表单有持续可见的 label、适当的 autocomplete、邮箱 input 类型、密码显示／隐藏、失焦校验及输入框附近的错误提示。异步操作显示进行状态并防重复提交；失败允许重试。不把未配置、账号密码错误、邮箱待确认混成“登录成功”。密码重置提示不泄露邮箱是否存在。

弹窗使用原生 dialog，支持键盘、Escape、清晰的关闭按钮、焦点约束及关闭后恢复到入口。账号模块加载失败不妨碍免费浏览或开发者打开地图。无障碍提示和恢复链接不能依赖颜色、悬浮或占位文字。

## 明确不包含

- 本阶段不真实收款、不创建订单、不向任何账号写入购买或管理员权限。
- 不用仅前端加锁冒充安全的付费内容保护。现有公开 HTML/JS 仍包含付费候选内容；正式收费前必须另做服务端鉴权和内容迁移。
- 不增加学习进度云同步、收藏、Facebook／微信登录或定价页面。
- 当前完整本地艺术史图片版和开发者世界史内容继续可用，不因为尚未登录而锁住。

## 验收与配置边界

自动测试覆盖表单校验、无配置、接口失败、待验证邮箱、会话过期、退出、恢复流程及回跳限制；浏览器验证电脑／手机布局、键盘、焦点和主页面地图不回归。依赖可控的认证适配器测试不等于真实供应商联调。

只有在 Tiffany 创建并配置项目后，才能以测试邮箱验证实际邮件送达、Google 跳转、真实账号建立与跨刷新会话。没有这些实际配置时，交付状态必须写作“代码与本地界面完成，真实认证待配置／联调”，不能标为正式上线可用。正式对学生开放前还需要实际隐私说明、适当的发信服务、限流／防滥用配置和区域网络测试。
